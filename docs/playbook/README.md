# Dreamcast port playbook

Traps that cost real time, symptom first, so the next port checks here before theorising. Each
row: what you see, why, what fixed it, where it was learned. Mechanism (applies to any game) is
kept apart from numbers (this game's addresses).

| # | Symptom | Cause | Fix | Source |
|---|---|---|---|---|
| T1 | Hundreds/thousands of untranslated calls to `0x8C000600` (or VBR+0x100/0x400/0x600) from frame 0 | Katana copies its exception/interrupt stubs below the load address at boot; VBR points there; the translator never saw that code at its run address | `--suggest-config FILE` lists `[[relocations]]` (source/size/dest); paste, rebuild | soulcalibur-recomp, 2026-10-05 (Soulcalibur VBR = 0x8C000000) |
| T2 | Game runs, music should play, report says `mixer: 0 key-ons` while `channel writes` is large | The sound driver keys voices with **32-bit** stores to AICA channel registers; the mixer only ran key-on for 16-bit writes | Engine: `Aica::reg_write` treats size 4 as 16-bit (as Flycast does). Fixed for all games | soulcalibur-recomp, 2026-10-05 |
| T3 | A RAM-patch enhancement (widescreen value written each vblank) crashes the translated build minutes in, while `--interpret` with the same patch runs clean | Translated code diverging from the interpreter once game state changes: an emitter defect the patch merely exposes | Treat as an emitter bug: replay/differential harness (`/dc-investigate` §4). Never "fix" by dropping the enhancement | soulcalibur-recomp, 2026-10-05 (open) |
| T4 | `.cue` dump rejected / user hand-writes a `.gdi` | Engine originally read only GDI/CHD | Engine now reads Redump `.cue` (HD area at LBA 45000, INDEX 01 = track start) | dreamcomp, 2026-10-05 |
| T5 | `dc.py shots` gets fewer screenshots than asked | `--max-frames` counts guest frames, `--screenshot-at` presented frames; or the run faulted (a half-written `.ppm` is the tell) | Leave headroom; check the run's `stop:` line | dreamcomp, 2026-10-05 |
| T6 | Characters/stage art green or purple; `--dump-textures` shows `*_yuv422` textures with a green/magenta cast while linear ones (portraits) look right | Twiddled (and VQ) YUV 4:2:2 decoded as memory-adjacent word pairs; the pair is horizontal, its words are not adjacent in twiddled order | Engine: 16-bit words gathered into scan order, then paired (`texture.cpp`). Check dumps first: a format-specific cast is a decoder bug, not shading | soulcalibur-recomp, 2026-10-05 |
| T7 | Effect sprites (dust, flames) drawn as solid black or pale boxes with the effect visible inside | The game sets list-type bits only on the list's first header; the decoder read them per header and put translucent sprites in the opaque list | Engine: list type latched until end of list (`display_list.cpp`). Diagnose by parsing the F11 `.ta` for headers in the box's screen rect and reading their PCW/TSP | soulcalibur-recomp, 2026-10-05 |
| T8 | Mipmapped floors/walls look speckled, grout lines doubled | Base-level offset padded by 1 texel instead of Flycast's 3 (16/8-bit), shifting the twiddled read by 2 texels | Engine: `OtherMipPoint` offsets in `texture.cpp` and `texture_pack.cpp`; a roughness probe (mean neighbour difference) on the captured VRAM tells the right offset | soulcalibur-recomp, 2026-10-05 |
| T9 | Windowed game far below real time while headless runs 4x faster | Per-frame GPU round trips: whole texture cache dropped with `vkDeviceWaitIdle` on every palette write, each frame read back to the CPU and re-uploaded, CPU waiting on the GPU after every render | Measure with `DREAM_PROFILE=1` first; palette-keyed cache, direct present, pipelined renders (Soulcalibur 0.3x → 4.1x at 2x scale) | dreamcomp, 2026-10-05 |
| T10 | Clicks every few seconds, audio 0.2 s behind the picture | Guest clock vs sound-card clock drift; the sink dropped whole blocks at a high-water mark | Dynamic rate control (±0.5 % playback ratio) holding a ~70 ms queue; `audio:` report line shows drops/underruns/ratio | dreamcomp, 2026-10-05 |
| T12 | HUD digits/text (timer, clock, names) or other alpha-tested sprites drawn on solid black boxes | The title never writes `PT_ALPHA_REF`; it relies on the power-on value 0xFF. Reset to 0, the punch-through test passes alpha-0 texels | Engine: PVR registers get Flycast's power-on values (`Core::reset`). Diagnose: `.ta` dump shows the sprite in list 4 (punch-through), `--dump-vram` regs show the threshold, `DREAM_PVR_WATCH=11C` shows no write | soulcalibur-recomp, 2026-10-05 |
| T13 | Characters float: no shadows on the floor | Modifier volumes were parsed but never drawn | Engine draws them (stencil, Flycast order). Check: `dreamcomp_ta_dump capture.ta` prints `modifier triangles N`; compare a shot with `DREAM_NO_MODVOL=1` | soulcalibur-recomp, 2026-10-06 |
| T14 | Second stage/character shows textures from the previous one (wrong patterns on rocks, boats, clothes) | The texture cache never saw guest writes to VRAM; a new image at an old address kept the old decode | Engine: dirty-page tracking in `DcMemory`, invalidation before each render. Check: report `textures: ... N dropped because the guest rewrote them`; compare with `DREAM_NO_VRAM_INVALIDATE=1` | soulcalibur-recomp, 2026-10-06 |
| T15 | Crash inside the GPU driver some time after a live aspect/size change | An object kept a handle to the destroyed render pass and created a pipeline with it later | Hand every holder the new pass when rebuilding (`Renderer::set_render_pass`). To reproduce such races, disable caches that pre-build objects (`DREAM_NO_PIPELINE_CACHE=1`); read the dump with `tools/crash_stack.py` | soulcalibur-recomp, 2026-10-06 |
| T16 | Game thread busy far above what the scene needs; profiler puts a quarter of it in one guest function's *self* time plus `call_indirect` and a tiny `fn_` | The Ninja vsync wait: a spin on a RAM flag calling an empty callback (`rts; nop`) each pass until the vblank interrupt clears the flag | Idle skip: hook the callback, `dreamcomp::IdleWait` (docs/HOOKS.md "Idle skip"); verify bit-identical against `DREAMCOMP_NO_IDLE_SKIP=1`. Same 22-cycle loop in both games so far | soulcalibur-recomp, jet-grind-radio-recomp, 2026-10-06 |
| T17 | Widescreen HUD still stretched although `hud.enabled`; an earlier check "looked right" because the stretched HUD still sits at the edges | The game draws its HUD as flat polygons, not sprites, so the sprite rule matched nothing | `ta_dump` summary `sprites 0` is the tell; `hud.polygons = true` plus an `overlay_z` under the HUD's 1/w. Check at `--aspect 21:9` by an element's width against 4:3, never by position | jet-grind-radio-recomp, 2026-10-06 |
| T18 | Upscaled only: thin grey frames around every character of a font (or around HUD art pieces) | Glyphs packed tight in the texture, drawn 1:1 bilinear: at 1x pixel centres hit texel centres, at 2x+ the edge pixels sample a quarter texel into the neighbour | `sharp_2d` (default on, docs/HUD.md "Sharp 2D"). Prove the cause first: `--set scale=1` makes the frames vanish | jet-grind-radio-recomp, 2026-10-06 |
| T19 | `--dump-textures` writes nothing / a texture pack replaces nothing; report `textures: 0 hashed` | Range bookkeeping meant for render-to-texture also caught the guest's own VRAM uploads (dirty pages), so every uploaded texture looked like a render target | Engine: `invalidate_range(..., rendered=false)` for guest writes. Check the `textures:` report line for `hashed` > 0 whenever a pack or dump is on | jet-grind-radio-recomp, 2026-10-06 |
| T20 | HUD editor outlines the whole screen as one element; every click edits the same override; menus, "TIME UP" or name bars stretch after promoting | A large override with the untextured word (0x00000000) pulled a full-screen fade into the HUD and grouping chained it with everything | Overrides skip pieces wider than `full_width` unless `full=1`; the editor refuses new overrides from screen-sized outlines. Review promoted files with `scenario.py --compare` against a run without them before committing | soulcalibur-recomp, 2026-10-07 |
| T21 | A scenario run diverges from its baseline part-way (screens and audio differ from some frame on), or the same exe gives two different runs | The scenario window takes real input: someone pressed keys while it ran | Rerun with nobody touching the machine; scenarios are deterministic only without live input | dreamcomp, 2026-10-07 |
| T22 | Playtest launched by `dc.py run --window`: the saved Resolution is ignored at start (log `drawing at 853x480` at scale 2) and the game cannot save (no `memory card` line) | The core applied the player's scale and card only for a double-click / `--launcher` start | Core: any `--window` run gets them (explicit flags still win). Check every playtest log for `memory card ...` and `drawing at` | dreamcomp, 2026-10-07 (Daniel's JGR session) |
| T11 | Occasional full-scale samples (clipping) in loud scenes | AICA output saturates after master volume (Flycast clamps identically) | Treat as authentic; do not "fix" accuracy with a limiter unless as an opt-in enhancement | soulcalibur-recomp, 2026-10-05 Re-checked 2026-10-06: line-by-line audit vs Flycast master -- mixer, DSP, tables and ARM7 costs identical with Flycast's DSP enabled (its default is DSP off, which is quieter and drops all effects). Remaining ticks: the sound driver re-keys a voice over ~4 samples (key off, rewrite registers incl. TL=0 for one sample, key on), audible as a tick; same in Flycast. Not the SDL resampler: a sine through SDL3 with the ratio changed every block shows no discontinuity (`work/sdltest/ratio.cpp`) |
